# 게시글 작성·상세 조회 실습 가이드

## 1. 게시글 작성

### 권장 API

`POST /api/posts`

요청 본문에는 `categoryId`, `title`, `content`를 담는다. 작성자 ID는 클라이언트가 보내지 않고 로그인 세션에서 구한다.

### 구현 순서

1. `PostRequest`에 카테고리, 제목(63자 이하), 내용(비어 있지 않음) 검증을 둔다.
2. Controller에서 세션의 `LoginMember`를 얻는다. 로그인하지 않았으면 `401`이다.
3. Service에서 `PostMapper.countCategoryById(categoryId)`로 존재하는 카테고리인지 확인한다.
4. 새 `Post`에 세션의 `memberId`, 요청의 카테고리·제목·내용을 채운다.
5. `PostMapper.insert(post)` 실행 후 생성된 `postId`로 다시 한 건을 조회해 응답한다.
6. JSP는 성공 시 `/post/detail/{postId}`로 이동시킨다.

### 확인할 점

- 로그인하지 않은 상태에서는 작성할 수 없다.
- 존재하지 않는 카테고리는 `400`이다.
- 회원 A가 작성해도 요청 본문을 바꿔 회원 B 명의로 등록할 수 없다.
- `post_id`가 자동 생성되고, `views` 초기값이 0인지 DB에서 확인한다.

## 2. 게시글 상세 조회

### 권장 API

`GET /api/posts/{postId}`

응답에는 카테고리명, 작성자명, 제목, 내용, 조회수, 작성·수정일을 포함한다. 비밀번호나 탈퇴 처리에 쓰이는 내부 정보는 포함하지 않는다.

### 조회수 규칙을 먼저 정하기

학습용으로는 상세 조회 때마다 `views = views + 1`을 수행해도 된다. 실제 서비스에서는 작성자 본인 제외, 같은 세션의 중복 조회 제한 같은 정책이 필요할 수 있다.

### 구현 순서

1. Controller에서 `postId`를 받는다.
2. Service에서 `incrementViews(postId)`를 수행한다.
3. 변경 행 수가 0이면 삭제됐거나 없는 글이므로 `404`를 반환한다.
4. `findById(postId)`로 게시글·카테고리·작성자 정보를 조회한다.
5. JSP에서 제목, 메타 정보, 내용, 수정·삭제 링크를 출력한다.

### 트랜잭션 질문

조회수 증가와 상세 조회를 한 Service 메서드 안에서 처리할 때, 둘을 하나의 트랜잭션으로 묶을지 토론해 보세요. 학습 프로젝트에서는 `@Transactional`을 붙여 두 SQL이 한 작업이라는 점을 보여주기 좋습니다.

## 완료 체크

- 작성 직후 상세 화면으로 갈 수 있다.
- 잘못된 글 번호는 `404`다.
- 상세를 새로고침했을 때 정한 정책대로 조회수가 변한다.
- 목록에서 보이던 카테고리·작성자 정보와 상세 정보가 일치한다.
